# Next steps for Vexis Engine 2

## Immediate production work

1. Add a real asset browser with thumbnail previews and reimport support for GLB/glTF and texture files.
2. Introduce actual content graph editing for quests and dialogue nodes rather than simple flat records.
3. Persist editor layout state so panels, tabs, and splitters survive restarts.
4. Connect the runtime bundle path to a real launch command that starts a packaged executable or local dev runtime.
5. Add terrain material layers, biome brushes, and river/road painting tools.
6. Replace the CPU-only preview with a true GPU-backed 3D viewport.

## Medium-term milestones

1. Implement transform gizmos, selection snapping, and entity-component world objects.
2. Add navmesh, collision, and physics generation from authored world data.
3. Add animation and audio asset preview inside the editor.
4. Introduce undo/redo history for world edits and content changes.
5. Add deterministic project cooking and packaging for runtime deployment.

## Long-term vision

1. Build a true content-authoring pipeline with live validation and AI-assisted automation.
2. Ship a polished Vaelor client experience with gameplay scripting, streaming, and runtime debugging.
3. Expand the desktop editor into a complete world/content production suite with multi-user collaboration hooks.
